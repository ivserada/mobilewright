# Тест-кейсы Android-приложения Vi

## 1. Объект тестирования

- **Приложение:** Vi, currency converter.
- **Application ID:** `com.vi`.
- **APK:** [app/curr_converter.apk](../app/curr_converter.apk).
- **Платформа:** Android.
- **Исследованное окружение:** эмулятор `Medium Phone API 37.0`, устройство `emulator-5554`.
- **Дата исследования:** 2026-11-16.
- **Основание:** исследование приложения на запущенном эмуляторе и просмотр логики JS-бандла APK. Требования и дизайн-макеты не предоставлены.

Документ содержит тест-кейсы, а не результаты полноценного тестового прогона. Фактические расхождения, обнаруженные во время исследования, вынесены в раздел [«Потенциальные дефекты»](#6-потенциальные-дефекты).

## 2. Обозначения и общие условия

### Приоритеты

- **P0** — критичная проверка работоспособности приложения.
- **P1** — основная функциональность и важные негативные сценарии.
- **P2** — дополнительные, UX, совместимость и accessibility-проверки.

### Общие предусловия

Если в кейсе не указано иное:

1. APK установлен на эмуляторе.
2. Приложение запущено на главном экране.
3. Выбрана исходная пара **USD → CAD**.
4. Поле суммы пустое.
5. Интернет доступен.
6. Устройство находится в портретной ориентации.

### Проверка результата конвертации

`R(FROM, TO)` — актуальный курс из FROM в TO. Для суммы `A` ожидаемый результат вычисляется как:

```text
A × R(FROM, TO), округлённый до двух знаков после запятой
```

Не следует фиксировать в проверках текущий курс или конкретный результат для USD/CAD: во время исследования результат для `10 USD` изменился с `14.29 CAD` на `14.28 CAD`.

Для offline-кейсов `R(FROM, TO)` — ранее сохранённый приложением курс.

## 6. Потенциальные дефекты

Приоритет здесь означает важность проверки/исправления, а не финальную severity дефекта. Окончательную severity нужно определить после согласования требований.

### BUG-001 — Числовой результат не пересчитывается после обмена валютами

- **Приоритет:** P1.
- **Связанный кейс:** VI-021.
- **Подтверждение:** воспроизведено на эмуляторе; причина также видна в логике APK — пересчёт запускается при изменении суммы, но не при изменении валютной пары.
- **Шаги:** ввести `10` для USD → CAD, дождаться результата, нажать кнопку обмена валютами.
- **Фактически:** коды меняются на CAD → USD и выражение становится `10 CAD =`, но число остаётся прежним. Например, вместо результата по курсу CAD/USD было показано прежнее `14.29 USD`.
- **Ожидаемо:** число пересчитывается для новой пары либо очищается до получения нового курса. Старое значение не должно выглядеть актуальным.

### BUG-002 — Прежний результат отображается для некорректной суммы

- **Приоритет:** P1.
- **Связанные кейсы:** VI-030, VI-031.
- **Подтверждение:** воспроизведено на эмуляторе.
- **Пример 1:** после `10 USD = 10.00 USD` ввести `abc` в паре USD → USD.
- **Фактически:** отображается `abc USD =`, но под ним остаётся `10.00 USD`.
- **Пример 2:** после конвертации `-10` ввести `10,5`.
- **Фактически:** отображается `10,5 USD =`, но результат остаётся `-10.00 USD`.
- **Ожидаемо:** некорректный ввод очищает результат или вызывает явное сообщение об ошибке. Результат предыдущей суммы не отображается как актуальный.

### BUG-003 — Отмена выбора валюты очищает введённую сумму

- **Приоритет:** P1.
- **Связанный кейс:** VI-018.
- **Подтверждение:** воспроизведено на эмуляторе; в APK очистка вызывается уже при открытии экрана выбора.
- **Шаги:** ввести `10`, дождаться результата, открыть `From`, затем вернуться системной кнопкой Back без выбора валюты.
- **Фактически:** валютная пара не меняется, но сумма очищается; после пересчёта пустого ввода отображается `0.00 CAD`.
- **Ожидаемо:** отмена не меняет ни валютную пару, ни сумму, ни результат.
- **Примечание:** если очистка при отмене является намеренным продуктовым решением, кейс VI-018 нужно скорректировать. См. Q-004.

### BUG-004 — Нет сообщения при отсутствии результатов поиска

- **Приоритет:** P2, UX.
- **Связанный кейс:** VI-015.
- **Подтверждение:** воспроизведено на эмуляторе.
- **Фактически:** после запроса `zzzz` отображаются только заголовок и поле поиска; область результатов пустая.
- **Ожидаемо:** отображается пояснение вида `No currencies found`, чтобы отличить пустой результат от незагруженного списка или ошибки.

### BUG-005 — Недостаточная доступность кнопки обмена и выбора валюты

- **Приоритет:** P2, accessibility.
- **Связанный кейс:** VI-054.
- **Подтверждение:** обнаружено в accessibility tree; требуется дополнительная проверка с TalkBack.
- **Фактически:** кнопка обмена представлена только символом иконки без понятного accessible name. Выбор валюты визуально обозначен радиокнопкой, но состояние не представлено как доступное `checked/selected`.
- **Ожидаемо:** у кнопки обмена есть доступное имя, например `Swap currencies`; код и название валюты, а также её выбранное состояние доступны screen reader.

## 7. Вопросы к требованиям

| ID        | Вопрос                                                                                           | Почему это важно                                                                                                 |
| --------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| **Q-001** | Разрешены ли отрицательные суммы и экспоненциальная запись (`1e3`)?                              | Сейчас используется JavaScript `Number`, поэтому такие значения могут конвертироваться как обычные числа.        |
| **Q-002** | Должна ли пустая сумма означать `0` и показывать `0.00`, или результат должен быть пустым?       | Текущая реализация преобразует пустую строку в ноль.                                                             |
| **Q-003** | Должна ли запятая поддерживаться как десятичный разделитель?                                     | Это влияет на локализацию и ожидаемый результат VI-031.                                                          |
| **Q-004** | Должна ли сумма очищаться при отмене выбора валюты?                                              | Определяет, является ли BUG-003 дефектом или намеренным поведением.                                              |
| **Q-005** | Всегда ли нужны два знака после запятой, включая валюты с нулевыми decimal digits, например JPY? | В данных валют есть `decimalDigits`, но текущий результат всегда форматируется через два знака.                  |
| **Q-006** | Нужны ли индикатор загрузки и срок актуальности курса?                                           | Во время запроса пользователь может видеть прежний результат; offline-кэш не показывает дату сохранённого курса. |

## 8. Рекомендуемый минимальный smoke-набор

Для быстрой проверки каждой новой сборки рекомендуется выполнить:

- **VI-001** — запуск и начальное состояние;
- **VI-002** — базовая online-конвертация;
- **VI-011 / VI-012** — выбор исходной и целевой валюты;
- **VI-021** — обмен валютами с пересчётом;
- **VI-030** — отсутствие устаревшего результата при некорректном вводе;
- **VI-040 / VI-041** — cached и uncached offline-сценарии;
- **VI-050** — восстановление приложения из фона.
